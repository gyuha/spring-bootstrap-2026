## Lens: Decisions/Surprises/Patterns/Mistakes
_Captured: 2026-05-31T03:20:00Z_

### Decisions
- D-01~D-09: 신규 auth 바운디드 컨텍스트, 2단계 oid→email 매칭, HttpSession 토큰 저장, 쿠키/CSRF, mock OIDC 테스트 (03-CONTEXT.md)
- Open Q 결정: SC#1/#4=WireMock 토큰 교환·/api 401 entrypoint·BaselineOidcUser Serializable 캐리어 (03-02-PLAN)
- 리뷰 수정: MeController null-tolerant 응답 + 조건부 oauth2Login 스킵 시 시작 WARN (commit 3520434)

### Surprises
- RESEARCH가 틀림 — `HttpSessionOAuth2AuthorizedClientRepository`는 프레임워크 기본이 아님(실제 Spring Boot 기본은 InMemory). SC#1 세션 read-back 테스트가 적발 (03-03-SUMMARY)
- `.csrf().spa()`는 Spring Security 6.5.1에 부재 → CsrfCookieFilter 수제 구현 필요
- `oauth2Login`이 ClientRegistrationRepository 빈 없으면 부팅 깨짐 → ObjectProvider 조건부 적용
- WireMock authorization-code 흐름(jwks 서명·nonce)이 MockMvc로 까다로움 — 실 token 교환 경로 직접 구동

### Patterns
- 선형 3 wave(deps→impl→test)로 전방참조 컴파일 위험 제거
- 포트/어댑터 + 동일 레이어 application 호출(auth.application→identity.application, ArchUnit ownLayer 허용)
- WireMock + jwks 서명 id_token + nonce echo로 충실한 OIDC mock
- SC 충실도는 WireMock 경로(oidcLogin 우회 금지 — 토큰 교환·실 Redis 세션 미증명)
- plan-checker revision loop(2 blocker 적발→수정→재검증 통과)
- 리뷰의 바이트코드 수준 검증(framework default 주장 실측)

### Mistakes
- RESEARCH의 거짓 "프레임워크 기본" 주장이 plan/CONTEXT로 전파됨
- Wave 3을 test-only로 계획했으나 NFR-02 충족 위해 main 코드(SecurityConfig) 교정 필요했음
- 조건부 oauth2Login 사일런트 미설정 footgun (WARN으로 완화)
- MeController `Map.of`가 null attribute에 NPE (singletonMap으로 교정)
