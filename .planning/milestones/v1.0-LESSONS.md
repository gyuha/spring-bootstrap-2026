- existsByEmail(Email) @Embeddable 파생 쿼리가 런타임에 정상 해석 — 예상했던 @Query override 불필요(Pitfall 6 미발현) (02-02/03-SUMMARY)
- ddl-auto: validate 부팅 성공 = AbstractAggregateRoot의 domainEvents가 @Transient로 자동 제외됨이 실증(A4 해소) (02-03-SUMMARY)

### Patterns
- 선형 3 wave(도메인→인프라→테스트)로 전방참조 컴파일 위험 구조적 제거 — Phase 1 lesson 적용, @Disabled 우회 불필요 (02-01~03-PLAN)
- 포트/어댑터 + 서비스는 포트만 주입 — application→infrastructure 0건(ArchUnit 정합) (02-02-SUMMARY)
- @RecordApplicationEvents+ApplicationEvents로 도메인 이벤트 발행 단언 (02-03)
- SC를 행위로 단언하기 위한 최소 placeholder 필드(internalNote) 도입 (02-01)
- 완료 단언 전 --rerun-tasks 독립 재검증 (orchestrator)

### Mistakes
- disable()가 미영속(id=null) 애그리거트에서 UserDisabled(null) 발행 가능 — 리뷰에서 적발, id 가드로 수정 (commit 2093bcd, 리뷰 Important #1)
- DB UNIQUE 동시성 위반 경로 미테스트 — 계획(IDEN-05)이 "UNIQUE 위반 단언"을 표방했으나 통합테스트는 선검사 경로만 검증. 리뷰에서 적발, dbUniqueConstraintRejectsDuplicateEmail 추가 (리뷰 gap)
- created_at 이중 소스(엔티티 Instant.now() + DDL DEFAULT now(), DB default 死) — Phase 1 SampleEntity와 동일 패턴이라 베이스라인 차원 미해소로 보류 (리뷰 Important #2)
- (운영 편의) Taskfile SERVER_PORT가 swagger/health URL 표시에만 쓰이고 bootRun 앱 포트에 미전달 — 혼잡 로컬 환경(8080/5432/6379 타 프로젝트 점유)에서 발견, --args 주입으로 수정

### Surprises
- RESEARCH가 틀림 — `HttpSessionOAuth2AuthorizedClientRepository`는 프레임워크 기본이 아님(실제 Spring Boot 기본은 InMemory). SC#1 세션 read-back 테스트가 적발 (03-03-SUMMARY)

- WireMock authorization-code 흐름(jwks 서명·nonce)이 MockMvc로 까다로움 — 실 token 교환 경로 직접 구동

### Patterns
- 선형 3 wave(deps→impl→test)로 전방참조 컴파일 위험 제거
- 포트/어댑터 + 동일 레이어 application 호출(auth.application→identity.application, ArchUnit ownLayer 허용)
- WireMock + jwks 서명 id_token + nonce echo로 충실한 OIDC mock
- SC 충실도는 WireMock 경로(oidcLogin 우회 금지 — 토큰 교환·실 Redis 세션 미증명)
- plan-checker revision loop(2 blocker 적발→수정→재검증 통과)
- 리뷰의 바이트코드 수준 검증(framework default 주장 실측)

### Mistakes
- RESEARCH의 거짓 "프레임워크 기본" 주장이 plan/CONTEXT로 전파됨
- Wave 3을 test-only로 계획했으나 NFR-02 충족 위해 main 코드(SecurityConfig) 교정 필요했음
- 조건부 oauth2Login 사일런트 미설정 footgun (WARN으로 완화)
- MeController `Map.of`가 null attribute에 NPE (singletonMap으로 교정)

# Lessons: Phase 4 (2026-05-31)

## Lens: Decisions/Surprises/Patterns/Mistakes
_Captured: 2026-05-31T11:57:20Z_
_Intent: capture technical decisions, unexpected outcomes, recurring techniques, and verification failures from this phase._

### Decisions
- D-03: PermissionEvaluator를 Spring Security `PermissionEvaluator`(hasPermission) 인터페이스가 아닌 application 계층 순수 `evaluate(userId,ResourceId,Action)` @Service로 배치 — Open Q1 해소, ArchUnit Application→Domain 게이트로 실증 (04-01-SUMMARY)
- D-04: AuthorizationPort는 evaluate/listObjects 읽기 판정만, grant/revoke는 AuthorizationApplicationService 책임으로 분리 (04-01-SUMMARY)
- D-07: 컨텍스트 간 userId/group_id/resource_id는 물리 FK 없는 soft reference — INVITED 사용자 존재검사 없이 grant 영속, ACTIVE 전이가 authorization 데이터 미접촉 (V3 / 04-02-SUMMARY)
- D-09: created_at 단일 소스(엔티티 `Instant.now()`, DDL 기본값 절 생략) — 이전 베이스라인 dual-source 패턴 회피 (04-01-SUMMARY)
### Surprises
- Wave 3에서 **Wave-2 소스 수정 0건** — 재귀 CTE/MyBatis 매핑/엔티티-DDL 정합·ddl-auto:validate가 첫 실행부터 GREEN. types-first 계약 고정이 추정 오류를 사전 차단함 (04-03-SUMMARY, 9dea173)
- 코드 리뷰가 ArchUnit이 구조적으로 못 잡는 누수를 적발: `@Param`(MyBatis)이 application PermissionReadPort에 있었으나 layered check는 third-party 의존을 안 봐 통과 (리뷰 Important #1, fcca22b)
### Patterns
- types-first 웨이브 분해: Wave1 도메인+계약 → Wave2 어댑터/CTE → Wave3 테스트. 컴파일 계약이 다음 웨이브를 강제 (04-01/02/03)
- 재귀 CTE는 실 Postgres Testcontainers(postgres:16)에서만 검증 — H2 금지, 사이클 가드는 실제 A↔B 사이클 입력 + assertTimeoutPreemptively로 행위 단언 (04-03-SUMMARY)
- 비롤백 @SpringBootTest 격리: 클래스별 AtomicLong 시퀀스 베이스(1M/2M/3M/4M/5M)로 고유 ID — 커밋이 필요한 즉시성 테스트(Pitfall 3)와 양립 (04-03-SUMMARY)
