# 로드맵 아카이브: v1.1 인증 웹 인터페이스 (SHIPPED 2026-05-31)

> BFF SPA가 소비할 인증 웹 인터페이스(REST)를 auth 컨텍스트에 제공한 마일스톤. PR #2(베이스라인 v1.0+v1.1).

## Phases (2)

### Phase 5: BFF 인증 세션 엔드포인트 — SHIPPED

**Goal**: BFF SPA가 401 노이즈 없이 인증 여부를 판별하고, JSON 흐름으로 로그아웃하며, OIDC 로그인에 진입할 수 있는 순수 인증 엔드포인트가 auth/interfaces 계층에 존재한다 (Identity/Authorization 집계 의존 없음)
**Requirements**: AUTH-06, AUTH-07, AUTH-10
**Plans**: 3/3 complete

**Success Criteria** (전부 ✅):
1. 비인증 `GET /api/auth/session` → 401 없이 `200 + {"authenticated":false}`, 인증 시 `{authenticated:true, userId}`
2. `POST /api/auth/logout` → 302 없이 `204`, HttpSession 무효화·SESSION 쿠키 삭제·이후 동일 세션 401
3. `GET /api/auth/login` → OIDC authorization 리다이렉트 + `returnTo` 복귀 (open-redirect 방지)
4. `/api/auth/session`·`/api/auth/login` permitAll, 기존 `/api/**` 401 엔트리포인트 불변

**구현**: SecurityConfig(logoutUrl→/api/auth/logout, HttpStatusReturningLogoutSuccessHandler 204, permitAll, RETURN_TO successHandler, registration id @Value 외부화) · AuthController(session/login, isSafeRelativePath open-redirect 방지, ObjectProvider 가드) · BffAuthSessionIT(7 tests). 코드 리뷰 C1(역슬래시 우회)·I1·I2·M2·M3 반영.

### Phase 6: 내 정보 신원·권한 집계 — SHIPPED

**Goal**: 인증 사용자가 `GET /api/auth/me` 한 번으로 신원(userId/email/status)과 권한(전역 역할·메뉴·리소스)을 받도록, auth/interfaces가 Identity·Authorization application을 교차 호출해 집계한다
**Requirements**: AUTH-08, AUTH-09, AUTH-11
**Plans**: 3/3 complete

**Success Criteria** (전부 ✅):
1. 인증 `GET /api/auth/me` → userId·email·status(Identity), 비인증 401
2. 동일 응답에 역할·메뉴·리소스 권한(Authorization) 단일 응답 포함
3. ArchUnit GREEN — auth/interfaces → Identity·Authorization application 교차 의존 허용

**구현**: IdentityApplicationService.findUser + AuthorizationApplicationService.findPermissions(@Transactional readOnly, direct grant) · UserView/PermissionView/MeResponse record(도메인·영속 애너테이션 interfaces 비노출) · AuthController.me() 교차 집계 · BffAuthMeIT(6 tests). ArchUnit 무변경 GREEN(D-06). 권한 direct only(D-02, 그룹/계층 상속 미포함 — 의도적). 코드 리뷰 I-1(unguarded principal→401) 반영.
